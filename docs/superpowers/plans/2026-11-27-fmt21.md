## Global Constraints
- German in UI, data, docs, commits and every message text; code comments English. Never use „Anforderung“, „Bedingung“ (for the situation), „Bedingungsraum“, „Ergänzende Merkmale“. „lernort“ only as accepted input alias. New visible words of this plan: „Anlass“, „Kernhandlung“, „Grundform“, „genannt“, „abgeleitet“, „angenommen“, „fehlt“, „ungeprüft“, „Rahmen“ (for r3/r4 methods).
- Core is the single source: reading, status, chain, selection per step, fallback, messages and readable names live in `@fmt/core`; REST and MCP call it. No second copy of a word list, a table or a label in server or web.
- REST = MCP: every changed answer is asserted on both sides (`/plan` ↔ `build_scenario_plan`, `/match` ↔ `match_scenario`, `/adapt` ↔ `adapt_scenario`).
- No LLM chooses a method. An LLM may read the free text (P3.6); the rules check what it read. The selection by an LLM among fitting candidates (spec E5, marked [H]) is not part of this plan.
- Data changes only through an independent gate. Files: `data/bausteine/*.json`, `data/vocab.json`, `data/ketten.json`, `data/teilgruppen.json`, `data/regeln.json`, new data files. The owner delegated the gates to an independent reviewer (an agent who did not write the proposal). Record per gate under `/mnt/project-files/fmt2/pruefung/` with every deviation and reason; the cautious reading wins. Code tasks use fixtures until the gated data is in.
- Exception stated per task: a code task may add a built-in rule or a text to `data/regeln.json` only where the task says so; rule count tests (`packages/fmt-core/test/regeln-zaehlung.test.ts`) and the Systematik page follow.
- `packages/fmt-core/test/qualitaet/ausgang.json` is never rewritten, `bekannt` is never loosened. A REIHE5 marker „wartet auf Q3/Q4/Q6/QD2“ is renamed to the task of this plan that fixes it (mapping in P0.1) and removed by that task.
- Status rule (E3): only stated (`genannt`) and derived (`abgeleitet`) values exclude; an assumed value only orders. Everything derived or assumed stands with its reason under the assumptions.
- No silent relaxing: a step nothing fits is a Grundform or a reported gap; every fallback stands under `hinweise`. No warning without basis: every new message names rule and Grundlage.
- Backwards compatible: existing valid requests keep working; answers gain fields. Row keys `step-N` stay positional. `maschinenlesbar.schemaVersion` (briefings.ts:1018, today „1.6“) is raised whenever its shape changes; the Baukasten import reads the new shape (test).
- TDD for code. `npm run build:data` before server and web tests. Green: core, server, web; `npm run qualitaet:ausgang` without Verschlechterung; variability checks in `qualitaet.test.ts` (häufigster Ablauf ≤ 15 %, sport starts ≥ 3).
- After each package: the condition check of P0.1 (`npm run szenariotest:bedingungen -- --paket N`), an independent review of the package diff, one fix wave, PR, green CI, then push and merge without asking again (owner, 27.11.2026). One PR per package.
